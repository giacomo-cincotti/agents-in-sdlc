GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat は、手元のマシンでリアルタイムに進む作業を表示します。ツールの実行やファイルの編集を確認し、各差分を受け入れたり取り消したりできます。追加のプロンプトを送ると、エディターを離れずに作業を調整または拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントに指示を追加し、ハイ コントラスト モードにライト モードの切り替えを加えます。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加してほしいという要望がありました。新しい会話を最初から始めずに、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. 作業中はチャットをスクロールし、各ツールの実行を確認します。ファイルの読み込みや編集、実行を求められたターミナル コマンドが表示されます。
3. ファイル編集が提案されると差分が表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度試させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。最後に変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。チャット セッションを続けることで、エージェントは以前の作業、変更したコンポーネント、スタイルの方針、local storage の使い方を保ったまま進められます。

1. Copilot Chat の入力欄に次のプロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を確認し、ライト モードの追加を提案します。
3. 新しい編集を確認し、それぞれ **Keep** または **Undo** を選びます。
4. たとえばトグル UI を意図しない形でリファクタリングするなど、期待と異なる方向に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を追加する方が、最初からやり直すより早く済みます。たとえば、「CSS を簡潔にするため、セレクターの重複ではなく CSS 変数を使う」「3 つ目のトグルを追加せず、既存の設定パネルにライト モードを組み込む」「両方のトグルにキーボード ショートカットを追加する」などと依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが含まれているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。アクセシビリティ用カスタム エージェントの指示に沿って、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が行われていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して案内しました。各ファイルの編集を確認し、変更を受け入れたり取り消したりし、コンテキストを保ったまま追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れたり取り消したりしました。
- 追加プロンプトを使い、作業中のセッションに指示を追加しました。

次のレッスンでは、アクセシビリティの変更をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
